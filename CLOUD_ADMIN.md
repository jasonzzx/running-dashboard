# Cloud admin

The public dashboard stays on Vercel. `/admin` requires a verified Neon Auth
session belonging to `jasonzzx@gmail.com`. The browser never receives database
credentials, encryption keys, Garmin keys or saved Strava refresh tokens.

## Data layout

- Private Vercel Blob store `running-dashboard-private`: the full historical
  DuckDB snapshot, source API responses, generated Parquet and dashboard artifacts.
- Neon database `running-dashboard-data`: activity summary index, encrypted provider
  connections, OAuth states, sync jobs, snapshot manifests and the published version.
- The master is a versioned cloud snapshot selected by PostgreSQL. DuckDB remains
  the analytics engine inside a disposable worker, preserving existing import and
  analysis semantics. PostgreSQL does not contain the 4.3 million recording samples.
- The original database on the Mac remains a backup. Cloud sync does not write to it.

## Weekly workflow

1. Sign in at `/admin` with the emailed verification code.
2. Connect Garmin with a Personal API key. Set the Strava application's callback
   domain to `running-dashboard-jason.vercel.app`, then authorize Strava once.
3. Click **同步最新数据 / Sync latest data**. The durable Vercel Queue continues
   after the browser closes. Each worker invocation has a bounded execution time;
   failed jobs retry up to three deliveries and preserve the published version.
4. Review counts, then click **发布仪表盘 / Publish dashboard**. PostgreSQL switches
   the public snapshot pointer atomically. No Git commit or redeployment is needed.

Provider IDs deduplicate new records. Existing non-null historical values remain
frozen; missing fields and cross-provider links may be enriched. Later syncs use
a seven-day overlap. Very old backdated uploads outside that window are not picked
up. Ambiguous matches are reported rather than double counted. Wellness is fetched
through yesterday and currently covers sleep, resting HR, steps, stress and weekly
HRV, as supported by the original connector.

## Validation and credentials

The Python worker builds a private candidate. A separate Node queue invocation
renders both analysis reports and validates all four bundles and every activity
detail. Only then does one database transaction accept the new master snapshot
and activity index. Publishing remains a separate explicit owner action.

Provider secrets use AES-256-GCM with `CLOUD_ENCRYPTION_KEY`, stored only in Vercel
environment variables. Strava refresh-token rotation is persisted immediately.
The Python worker accepts only timestamped HMAC-signed requests from the queue
function. All admin mutations require both a verified owner session and a matching
request origin. The public artifact route only serves an allowlist of generated
dashboard paths from snapshots explicitly marked published.

## Operational limits

The initial migration and subsequent snapshots consume private Blob storage.
This first release retains snapshots and Parquet exports; storage grows with each
sync. Review usage in Vercel Storage before approaching the account's quota.
Large catch-up imports can exceed the worker's 270-second execution budget. The
job fails safely instead of partially publishing. This workflow targets weekly
updates, not bulk reimports.

Readiness, acute/chronic training load and other unsupported daily endpoints keep
their historical values. Numerical analysis is recomputed; the independently
authored English and Chinese narrative templates are reused, not regenerated by AI.

## Setup and tests

`scripts/prepare_cloud_migration.py` prepares a private local ZIP. After explicit
upload authorization, `scripts/migrate_cloud.mjs` validates the SQL migration,
uploads the initial snapshot and verifies activity counts. It refuses to overwrite
an initialized dataset. Do not commit `.env.local` or anything under `data/`.

Run `npm run build`, `npm run test:cloud`, the browser test in
`tests/check_cloud_browser.cjs`, and `tests/check_sync_pipeline.py`. Real owner OTP
and provider OAuth/API tests require the user's live authorization; mocks do not
establish a successful live sync.
